Investigación: Hermes Agent + orquestación multi-LLM para abaratar tokens

2026-06-27 · Para JV · Fuentes: GitHub oficial de Nous Research, docs oficiales, DeepClaude, búsquedas web (junio 2026). Nivel de confianza marcado por sección.

TL;DR — las respuestas cortas
  • Qué es: Hermes Agent (Nous Research, open-source, feb 2026) es un agente que vive en un servidor y te habla por Discord/Telegram. Soporta 200+ modelos (Claude, GPT, Gemini, DeepSeek, GLM/z.ai…) y puede lanzar sub-agentes en paralelo = varias líneas de proyecto a la vez.
  • El loop que viste (abaratar tokens): un modelo caro e inteligente planea y revisa, un modelo barato (DeepSeek/GLM) hace el bulk de escritura, y se itera con feedback hasta cumplir el objetivo. Ahorro reportado ~56% ($0.19 vs $0.43 por tarea) con mejor accuracy.
  • Hosting: VPS barato gana (Hostinger/Contabo, ~$5/mes, 1 vCPU/1GB alcanza porque el LLM corre por API). NO necesitás Mac mini ni dejar tu compu prendida 24/7.
  • Discord vs Telegram: Discord = varios canales = varias líneas de proyecto aisladas. Telegram = una conversación lineal. Hermes maneja ambas desde un solo proceso gateway.
  • Caveat grande: el ahorro viene del routing por modelo, no del multi-agente. Mal configurado, un sistema multi-agente gasta 1-2 órdenes de magnitud MÁS tokens. La disciplina (exit conditions, budgets) es lo que lo hace barato.

1 · Qué es Hermes Agent (en su totalidad) fuente oficial

Hermes Agent es el agente de IA open-source y self-improving de Nous Research (lanzado febrero 2026). La idea central: en vez de abrir una terminal cada vez, el agente corre permanentemente en un host (tu compu, un VPS, Docker) y te llega por una app de mensajería. Es un competidor del estilo "agente personal 24/7".

Lo que lo distingue de Claude Code "pelado":

  • Learning loop incorporado: "the only agent with a built-in learning loop — it creates skills from experience, improves them during use." Crea sus propias skills tras tareas complejas y las mejora con el uso.
  • Memoria persistente de 3 niveles: búsqueda full-text (FTS5) de sesiones + resumen por LLM para recall entre sesiones + modelado del usuario (te "conoce" más con el tiempo). Esto es lo que CLAUDE.md + auto memory hacen en Claude Code, pero más automático.
  • 200+ backends LLM: Nous Portal, OpenRouter (200+ modelos), DeepSeek, z.ai/GLM, Kimi/Moonshot, MiniMax, NVIDIA NIM, OpenAI, Gemini, Hugging Face, o tu propio endpoint. Se cambia con hermes model — sin tocar código.
  • 40+ tools: web search, generación de imágenes, acceso a terminal, browser automation, etc.
  • Gateway multi-plataforma: Telegram, Discord, Slack, WhatsApp, Signal, email y CLI — todo desde un solo proceso.
  • 6 backends de ejecución: local, Docker, SSH, Daytona, Singularity, Modal.
  • Multi-agente: orquestador + workers (research, implementation, review, QA), cada worker con su propio contexto y tools, devolviendo un artefacto verificable.
Confianza de fuentes — leelo Las fuentes confiables son el repo de GitHub de Nous Research y los docs oficiales. Hay muchísimo contenido SEO alrededor (blogs tipo "hermes-agent.ai", "hermes-agent.org", Medium con títulos "GRATIS con DeepSeek V4") que exagera o inventa. Tratalos como pistas, no como verdad. Cualquier claim de "gratis" es clickbait: DeepSeek es barato, no gratis.

2 · El patrón estrella: loop multi-LLM para abaratar tokens verificado

Esto es lo que viste en el video. El nombre genérico del patrón es "orchestrator routing" o "DeepClaude". Hay dos variantes y conviene no confundirlas:

Variante A — DeepClaude clásico (razonar barato, ejecutar caro)

Según DeepClaude: DeepSeek razona (genera un "thinking trace": descompone el problema, identifica edge cases, arma el plan) y le pasa ese contexto a Claude Code que ejecuta (abre archivos, escribe, corre tests, se auto-corrige en loop). Acá Claude es a la vez ejecutor y revisor vía su propio agent loop.

Variante B — Cost-first (planear/revisar caro, escribir barato) ← la que te interesa

La que optimiza factura: un modelo caro e inteligente (Opus 4.8) actúa de orquestador — planea y revisa — y rutea el bulk de escritura de código a un modelo barato (DeepSeek o GLM). Pagás tarifa cara por pocas decisiones de alto nivel, y tarifa barata por el grueso de los tokens generados. El loop: orquestador define objetivo → worker barato escribe → orquestador revisa contra el objetivo → da feedback → worker corrige → repite hasta cumplir (con un máximo de iteraciones).

Números reportados (DeepClaude, refactoring) $0.19/tarea vs $0.43 usando solo Claude → ~56% más barato. Y mejor accuracy: 89% (híbrido) vs 74% (Claude solo) vs 61% (DeepSeek solo). El trade-off es tiempo: 6.1 min vs 4.2 min. Verificá estos números en tu propio eval set — vienen de un benchmark puntual, no son ley.

Por qué funciona: explota la capacidad de cada modelo. Razonar/arquitectura/revisar (alto valor, pocos tokens) → modelo caro. Escribir boilerplate/implementar (mucho volumen, bajo valor por token) → modelo barato. Es la regla del 80/20 de la L15 del curso, aplicada entre proveedores.

La paradoja multi-agente (no la ignores) Los sistemas multi-agente suelen consumir 1 a 2 órdenes de magnitud MÁS tokens que un agente solo: cada loop re-invoca planning, generación y reflexión, acumulando contextos largos. El ahorro NO viene de "usar varios agentes" — viene de rutear el volumen a un modelo barato y de cortar el loop con exit conditions. Sin disciplina, este patrón te sale MÁS caro, no menos.

3 · Cómo se conectan los distintos modelos (Claude, GPT, Gemini, DeepSeek, GLM)

Hermes abstrae el proveedor. La vía más simple para tener "todos los modelos" con una sola API key es OpenRouter (un proxy que expone 200+ modelos detrás de una key). Alternativamente conectás cada proveedor directo (más barato por token, más config).

  • Cambiar de modelo: hermes model — sin cambios de código, sin lock-in. Podés cambiar de DeepSeek a Claude a un modelo local con un cambio de config a mitad de workflow.
  • Routing por rol (el corazón del ahorro): asignás modelo distinto al orquestador vs a los workers. Orquestador = Opus 4.8 / razonador fuerte; workers de implementación = DeepSeek o GLM-4.6 (z.ai, muy barato para coding).
  • GLM/z.ai y DeepSeek son los favoritos "baratos para coding" del ecosistema 2026. Gemini Flash para velocidad. GPT para tareas donde rinda mejor en tu eval.

4 · Discord vs Telegram — múltiples líneas de proyecto

Tu intuición es correcta. La diferencia operativa:

AspectoTelegramDiscord
EstructuraChats lineales (1 conversación = 1 hilo largo)Servidor con múltiples canales + threads
Líneas de proyectoCuesta separar: todo se mezcla en una sesión consecutivaUn canal por proyecto → contextos aislados en paralelo
Sub-agentes paralelosPosible pero confuso de seguirEncaja natural: cada canal/thread = un workstream
SetupMás simple (un bot token, andá)Un poco más (server + bot + permisos de canal)

Hermes corre ambas desde el mismo proceso gateway, así que no elegís una para siempre. Para lo que querés —varias líneas de proyecto sin que se pisen— Discord es la mejor opción, apoyándose en que Hermes puede "spawn isolated subagents for parallel workstreams, each getting its own conversation and terminal."

6 · Optimización de tokens — explotar cada modelo por su capacidad

Resumen operativo de todo lo anterior, como checklist:

  1. Routing por rol: caro para planear/revisar, barato para el bulk. Es la palanca #1.
  2. Exit conditions explícitas: "iterá hasta que pasen todos los tests, máximo N iteraciones". Sin esto, el loop se desboca y el ahorro desaparece.
  3. Context budgeting: limitar cuánto contexto arrastra cada handoff entre modelos (el middleware de DeepClaude lo hace).
  4. Zero-context-cost turns: Hermes deja escribir scripts Python que llaman tools vía RPC, colapsando pipelines multi-step en un turno sin costo de contexto. (Es el patrón "code-over-tools" / Ubertools de Ronacher — está en la L10/L13 del curso.)
  5. Prompt caching: mantené estable la parte fija del prompt (system, instrucciones) para pagar solo el delta (L15 del curso).
  6. Modelo mínimo viable por tarea: no uses Opus para lo que GLM resuelve. Subí solo cuando tu eval muestre que el barato no llega.

7 · Setup paso a paso (camino recomendado)

Antes de seguir Estos pasos son la síntesis de los docs oficiales + guías de la comunidad. Los comandos exactos pueden cambiar entre versiones — confirmá siempre contra los docs oficiales al momento de instalar. No corras scripts de blogs random sin leerlos.
  1. Conseguí un VPS (Hostinger/Contabo, plan más chico, Ubuntu). Entrá por SSH.
  2. Requisitos: Git + Python 3.11+ (en Windows el instalador trae uv, Python, Node, ripgrep, ffmpeg y Git Bash portable).
  3. Instalá Hermes: script de instalación para Linux/macOS/WSL2 (o el desktop installer en Win/Mac).
  4. Autenticá: hermes setup --portal — una credencial OAuth cubre acceso a modelos + tools (web search, imágenes, TTS, browser).
  5. Configurá modelos: agregá tu key de OpenRouter (camino fácil) o keys directas de DeepSeek/Anthropic/z.ai. Definí el routing por rol (orquestador caro, workers baratos).
  6. Conectá Discord: creá un bot en el Discord Developer Portal, copiá el token, configuralo en el gateway de Hermes, invitá el bot a tu server. Un canal por proyecto.
  7. Probá chico: una tarea simple end-to-end antes de armar el loop multi-modelo. Verificá costos con tareas reales.

Alternativa más simple si te asusta el VPS: DeepClaude con Docker

Si solo querés el loop Claude+DeepSeek sin todo Hermes: cloná DeepClaude, copiá .env.example → .env, agregá las keys de Anthropic y DeepSeek, seteá el token budget, y docker compose up. Más acotado, ideal para entender el patrón antes de escalar a Hermes.

8 · Plan de acción concreto para vos

  1. Fase 0 — entender el loop (local, 1 tarde): probá DeepClaude con Docker en tu compu. Objetivo: ver el ahorro real en una tarea tuya. Cero compromiso de infra.
  2. Fase 1 — VPS mínimo: si te cierra, levantá un VPS de $5 e instalá Hermes. Conectá Telegram primero (más simple) con UN modelo.
  3. Fase 2 — multi-modelo + Discord: agregá routing por rol (Opus 4.8 orquesta, DeepSeek/GLM escriben) y migrá a Discord con un canal por proyecto.
  4. Fase 3 — medí: armá un mini eval set (5-10 tareas tuyas) y compará costo/calidad Hermes-loop vs Claude Code solo. Decidí con datos, no con el video.
Conexión con tu harness actual Esto NO reemplaza Claude Code para tu trabajo diario — es una herramienta para proyectos donde el volumen de código generado es alto y el costo importa (ej: SpagBook features grandes). Las skills que instalaste (grill-me → to-prd → to-issues → tdd) son el "plan" que un orquestador Hermes podría ejecutar ruteando el /tdd a un modelo barato. Mismo mindset, otra capa.

9 · Riesgos y cosas que verificar

  • Seguridad (lethal trifecta, L6): un agente 24/7 con acceso a tu código + internet + comunicación externa es la trifecta completa. Corré en VPS aislado, con keys de bajo privilegio y cap de gasto. Nunca tu cuenta de producción.
  • Costo real: el multi-agente puede gastar más si el loop no tiene exit conditions. Medí desde el día 1.
  • Calidad de fuentes: el 80% de lo que se escribe sobre Hermes es SEO. Confiá en GitHub oficial + docs.
  • Madurez: Hermes es de feb 2026, joven. Esperá cambios de API y bugs. No lo pongas en un flujo crítico todavía.
  • Modelos: usá Opus 4.8 (default actual) como orquestador. Fable 5 está suspendida por la directiva de export control de US (junio 2026).
