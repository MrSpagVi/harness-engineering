TL;DR — la respuesta
  • Worker por defecto: DeepSeek V4-Flash. Ganador claro en costo: ~$0.14/M input · $0.28/M output (cache hit baja input a $0.0028/M), 1M de contexto, pesos MIT. En un benchmark independiente fue el más rápido (2m35s) y el más barato viable (~$0.01/run, Tier B 78/100).
  • Worker "premium" cuando una feature necesita mejor código de una: GLM-4.6 (Z.AI/Zhipu) — $0.43/$1.74 en OpenRouter ($0.6/$2.2 API oficial), ~203K ctx. La familia GLM lidera el coding open-weight; GLM-5.2 (jun 2026) ya superó a 4.6.
  • Aún más barato para tareas chicas: Qwen3-Coder 30B A3B ($0.07/$0.27).
  • Orquestador (planea + revisa): tu Opus 4.8 — confirmado como el rol correcto para el modelo caro.
  • Regla estructural: parametrizá el modelo por env var, NO lo hardcodees. Estos modelos rotan en semanas (V4 reemplazó V3; los slugs viejos se retiran el 2026-07-24).

Hallazgos confirmados

DeepSeek V4-Flash: el más barato y rápido alta · 3-0

~$0.14/M input (cache miss), $0.0028/M (cache hit), $0.28/M output, 1M ctx, MIT. La página oficial de pricing lo confirma carácter por carácter; corroborado por OpenRouter, morphllm, cloudzero, fireworks. En el benchmark de akitaonrails (abril 2026) fue el worker más barato viable (~$0.01/run) y el más rápido (2m35s vs 8m+ del resto), 78/100 Tier B. Único defecto observado: escribió mal un slug de modelo que rompía el deploy.

El cache-hit de DeepSeek puede cambiar el cálculo alta

En un loop con system prompt fijo (exactamente tu caso en Hermes), el input repetido cae a $0.0028/M — dos órdenes de magnitud más barato que el cache-miss. Esto puede bajar el costo efectivo del worker dramáticamente. Es una de las preguntas abiertas a medir.

GLM-4.6 como escalón de calidad alta · 3-0

$0.43/$1.74 (OpenRouter) o $0.6/$2.2 (API oficial), 202.752 ctx, max output 128K. La familia GLM lidera SWE-Bench Verified entre open-weights y rinde bien en herramientas de agente (Claude Code, Cline, Roo Code). La paridad "con Sonnet 4" es stat de vendor — tomala con pinzas media · 2-1.

GLM-5.1 / 5.2 ya superaron a 4.6 alta

GLM-5.2 encabeza el subset open-source de coding (Quality Index 51.1, ~$1.72/M, 1M ctx, MIT). VentureBeat: "GLM-5.2 beats GPT-5.5 on multiple long-horizon coding benchmarks." GLM-5.1: $1.40/$4.40, 200K ctx, AA Coding 43.4. Si vas a worker premium, evaluá GLM-5.2 antes que 4.6.

Qwen3-Coder: el piso de precio alta · 3-0

30B A3B Instruct a $0.07/$0.27 (160K en OpenRouter, nativo 256K), 480B A35B a $0.22/$0.90 (262K). Bueno para tareas chicas o de mucho volumen donde la calidad importa menos.

Cambio de slugs — no hardcodear Los modelos de DeepSeek ahora son deepseek-v4-flash y deepseek-v4-pro. Los viejos deepseek-chat (V3) y deepseek-reasoner se retiran el 2026-07-24. Parametrizá el modelo por variable de entorno en tu setup Hermes.

Lo que NO quedó confirmado (señales importantes)

El patrón cheap-worker+reviewer no siempre gana

El mismo benchmark de akitaonrails argumentó que un único modelo top-tier superó a la orquestación multi-modelo, porque los workers baratos metían más bugs de lo que ahorraban en tokens. Este claim quedó refutado (0-3) en la verificación — o sea, NO está establecido como verdad — pero es una señal roja: el ahorro depende de tu tarea. Medí costo-vs-bugs en tu propio eval de SpagBook antes de comprometerte.

  • NO uses estos números (refutados): Opus 4.8 a $5/$25 por M (0-3, dato de un blog, no oficial); Kimi K2.6 y MiniMax M3 como "top workers" (0-3 y 1-2).
  • Los scores agregados de benchlm.ai (84.1, 88.7) son una escala propietaria no reproducible — solo el ranking direccional es confiable.

Recomendación accionable para tu setup Hermes

  1. Orquestador = Opus 4.8 (planea + revisa).
  2. Worker default = DeepSeek V4-Flash (costo imbatible + 1M ctx que aguanta el codebase de SpagBook entero + cache-hit barato para system prompt fijo).
  3. Worker premium = GLM-4.6 (o GLM-5.2) cuando una feature compleja necesite mejor código de una.
  4. Acceso: todos disponibles vía API directa y OpenRouter. OpenRouter = una sola key para todos (más simple); API directa = más barato por token (más config).
  5. Parametrizá por env var (ej. WORKER_MODEL, ORCHESTRATOR_MODEL) — la rotación de modelos es semanal.
  6. Cortá el loop: exit conditions ("máx 10 iteraciones o hasta tests verdes"). Sin esto, los bugs del worker barato se comen el ahorro.
Próximo paso concreto Antes de montar Hermes completo: corré DeepClaude con Docker (Opus 4.8 + DeepSeek V4-Flash) sobre 3-5 tareas reales de SpagBook. Medí: $/tarea, bugs introducidos, tiempo de review. Si el neto te conviene, escalás a Hermes en un VPS. Si no, te quedás con un solo modelo top-tier — y ya lo sabés con datos, no con un video.

Preguntas abiertas (lo que esta investigación no cierra)

  • ¿El neto realmente ahorra para JV, o los bugs del worker barato consumen tiempo de review de Opus y lo vuelven más caro? → eval propio.
  • ¿Cómo rinde V4-Flash en agentic tool-use / multi-turn (lo que un loop Hermes ejercita), no solo generación one-shot? Los benchmarks citados son mayormente single-task.
  • ¿GLM-5.2 como worker premium en lugar de 4.6? Falta comparar su output real y latencia en el rol.
